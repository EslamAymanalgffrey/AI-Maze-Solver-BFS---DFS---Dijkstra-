# 🧩 Maze Solver — BFS · DFS · UCS

تطبيق Python تفاعلي يُظهر بصرياً كيف تعمل خوارزميات البحث الثلاث على حل المتاهات خطوة بخطوة.

مبني بـ **Python 3 + Tkinter** فقط — بدون أي مكتبات خارجية.

---

## 📁 هيكل المشروع

```
maze_solver/
│
├── main.py          ← نقطة الدخول — شغّل هذا الملف
├── gui.py           ← واجهة Tkinter، رسم الشبكة، الأنيميشن، الإحصائيات
├── algorithms.py    ← تنفيذ BFS و DFS و UCS
└── utils.py         ← توليد متاهة عشوائية، تنسيق الوقت
```

## 🧠 شرح الخوارزميات

### BFS — Breadth-First Search (البحث بالعرض أولاً)

**الفكرة:** يستكشف كل الخلايا على مسافة 1، ثم مسافة 2، ثم 3... وهكذا.

**هيكل البيانات:** طابور FIFO (`collections.deque`)

```
طابور: [Start]
الخطوة 1: أخرج Start → أضف جيرانه للطابور
الخطوة 2: أخرج الجار الأول → أضف جيرانه
الخطوة 3: استمر حتى تصل للهدف
```

**مثال بصري:**
```
S → 1 → 2 → 3
↓   ↓   ↓
1   2   3
↓
1
```
*يتوسع كالموجات المتحدة المركز*

| الخاصية | القيمة |
|---------|--------|
| هيكل البيانات | طابور FIFO |
| أقصر مسار؟ | ✅ نعم (في الشبكات غير الموزونة) |
| التعقيد الزمني | O(V + E) |
| التعقيد المكاني | O(V) |
| الأفضل لـ | إيجاد **أقصر مسار** |

---

### DFS — Depth-First Search (البحث بالعمق أولاً)

**الفكرة:** يتبع مساراً واحداً حتى النهاية، ثم يرجع للخلف عند الوصول لطريق مسدود.

**هيكل البيانات:** مكدّس LIFO (قائمة Python)

```
مكدّس: [Start]
الخطوة 1: أخرج Start → أضف جيرانه للمكدّس
الخطوة 2: أخرج آخر جار أُضيف → اغص فيه
الخطوة 3: إذا وصلت لطريق مسدود → ارجع (pop التالي)
```

| الخاصية | القيمة |
|---------|--------|
| هيكل البيانات | مكدّس LIFO |
| أقصر مسار؟ | ❌ لا — يجد *أي* مسار |
| التعقيد الزمني | O(V + E) |
| التعقيد المكاني | O(V) |
| الأفضل لـ | استكشاف المسارات، الاستخدام العام |

---

### UCS — Uniform Cost Search (البحث بالتكلفة الموحدة)

**الفكرة:** دائماً يوسّع العقدة ذات أقل تكلفة تراكمية من البداية.

**هيكل البيانات:** طابور أولوية Min-Heap (`heapq`)

```
Heap: [(تكلفة=0, Start)]
الخطوة 1: أخرج الأرخص تكلفة
الخطوة 2: أضف الجيران مع تكلفتهم الجديدة
الخطوة 3: دائماً اعالج الأرخص أولاً
```

| الخاصية | القيمة |
|---------|--------|
| هيكل البيانات | Min-Heap (طابور الأولوية) |
| أقصر مسار؟ | ✅ نعم (حتى مع تكاليف مختلفة) |
| التعقيد الزمني | O((V + E) · log V) |
| التعقيد المكاني | O(V) |
| الأفضل لـ | الشبكات بـ**تكاليف مختلفة** (طرق، تضاريس) |

## ⚖️ مقارنة الخوارزميات

```
┌─────────────────┬──────────┬──────────┬────────────┐
│                 │   BFS    │   DFS    │    UCS     │
├─────────────────┼──────────┼──────────┼────────────┤
│ هيكل البيانات  │ طابور    │ مكدّس    │ Min-Heap   │
│ يوسّع           │ الأقرب   │ الأعمق   │ الأرخص     │
│ مسار مثالي؟    │ ✅ نعم   │ ❌ لا    │ ✅ نعم     │
│ مكتمل؟*        │ ✅ نعم   │ ✅ نعم   │ ✅ نعم     │
│ السرعة          │ متوسطة   │ سريع     │ أبطأ       │
│ الذاكرة         │ عالية    │ أقل      │ عالية      │
├─────────────────┼──────────┼──────────┼────────────┤
│ في متاهتنا     │ مثالي    │ أي مسار  │ = BFS      │
│ (تكلفة موحدة)  │          │          │            │
└─────────────────┴──────────┴──────────┴────────────┘

* "مكتمل" = يجد مساراً دائماً إذا كان موجوداً
```

### ملاحظة مهمة عن الشبكة الموحدة
في متاهتنا كل خطوة تكلف 1. لذلك:
- **BFS و UCS** يعطيان نفس المسار الأمثل تماماً
- **UCS** يتفوق حقاً عندما تكون التكاليف مختلفة (مثلاً: المرور في الماء يكلف 3، والعشب يكلف 1)

---

## 💡 أسئلة للمناقشة

**1. لماذا يضمن BFS أقصر مسار؟**
لأنه يستكشف كل العقد على مسافة *d* قبل أي عقدة على مسافة *d+1*. أول مرة يصل للهدف = أقل عدد خطوات.

**2. لماذا لا يضمن DFS أقصر مسار؟**
يلتزم باتجاه واحد مبكراً وقد يصل للهدف عبر مسار طويل جداً دون فحص البدائل الأقرب.

**3. متى نستخدم UCS بدلاً من BFS؟**
في الشبكات ذات التكاليف المختلفة. BFS يعامل كل الحواف بالتساوي (خطأ)، UCS يأخذ التكلفة بالحسبان (صح).

**4. ما هو قاموس `parent`؟**
كل عقدة تُسجّل من اكتشفها. بعد الوصول للهدف، نتتبع المؤشرات للخلف: `goal → ... → start` لإعادة بناء المسار.

**5. ماذا يحدث إذا لم يوجد مسار؟**
الخوارزمية تستنزف كل الخيارات دون الوصول للهدف. `reconstruct_path` ترجع `[]` وتظهر الرسالة "❌ لا مسار".

## 🏗️ معمارية الكود

```
main.py
  └── MazeSolverGUI  (gui.py)
        ├── _build_ui()          — بناء كل عناصر Tkinter
        ├── _init_canvas()       — رسم خلايا الشبكة الأولية
        ├── أحداث الفأرة         — _on_click, _on_drag, _on_right_click
        ├── _run(algo, name)     — تشغيل الخوارزمية وقياس الوقت
        └── _animate()           — أنيميشن خطوة بخطوة عبر root.after()
              └── يستدعي: algorithms.py  (bfs / dfs / ucs)
                          utils.py       (format_time)
```

### لماذا `root.after()` وليس Threads؟
Tkinter **غير آمن مع الخيوط (not thread-safe)**. استخدام `root.after(delay, callback)` يجدول إطار الأنيميشن التالي على حلقة الأحداث الرئيسية — الواجهة تبقى متجاوبة دون تجميد.
